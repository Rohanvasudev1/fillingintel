RECOMMENDATION

  PARSER: Use edgartools (edgar.documents.parse_html) for section detection.

  Rationale:

  1. Section structure. edgartools returns a clean, flat list of SEC-standard
     section names (e.g. part_i_item_1a, part_ii_item_8) derived from the
     HTML semantics of the filing. NVDA and AMD 10-Ks each yield 24 sections
     covering Parts I–IV with all Items. This is exactly the granularity
     needed to produce ParsedSection records and retrieve named passages.

  2. Table survival. edgartools detects markedly more tables than sec-parser
     (640 vs 325 across 6 filings). The HTML <table> elements are preserved
     and accessible via doc.tables, which is a prerequisite for chunking
     financial tables separately.

  3. TOC false positives. Both parsers score 0. Neither is tricked by the
     Table of Contents entries in the filings sampled.

  4. sec-parser disqualifying failures:
     a) No 10-K parser. The library only ships Edgar10QParser. When applied
        to 10-K filings it emits 12–14 "InvalidTopSectionIn10Q" warnings and
        produces 224 raw element-level objects rather than a structured section
        map, requiring substantial post-processing.
     b) INTC catastrophic failure. Both INTC filings (10-K and 10-Q) return
        only 12–18 elements, all of which are cover-page boilerplate ("UNITED
        STATES SECURITIES AND EXCHANGE COMMISSION", "FORM 10-K", etc.).
        Every required section is missing. This makes sec-parser unreliable
        for production use against INTC's filing format.

  5. Char-offset accuracy. edgartools get_sec_section() text is NOT a direct
     slice of doc.text() — the two use slightly different whitespace
     normalization (only 3/29 whitespace-normalised round-trips pass). This
     means char_start/char_end in ParsedSection cannot be derived by looking
     up get_sec_section() output in doc.text(). Instead, the parser layer
     should: (a) call doc.text() as the canonical full-text string, and
     (b) locate each section via whitespace-normalised search in that string
     to compute char offsets. The section text itself is correct; only the
     direct indexing path needs this extra step.

  6. Missing required sections in 10-Qs. Both parsers miss part_ii_item_1a
     (Risk Factors for 10-Q) on several filings. Investigation needed in
     Step 2b: some 10-Qs omit Part II Item 1A when there are no material
     changes; the parser correctly reflects the absence. Verify per ticker
     before treating this as a parser defect.

  FISCAL PERIOD: all 6 dei tags match derive_fiscal_period(). No mismatches.
  The algorithm is correct for NVDA, AMD, and INTC; retain it as-is. The dei
  tags confirm that the FY2025/FY2026/FY2027 numbering is correct and that
  the NVDA late-January FYE edge case is handled correctly.
